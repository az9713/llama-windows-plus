Llama Browser Buttons

Four buttons for the Chrome bookmarks bar. Each button sends the text that you selected, or the whole page, to Gemma in Llama on this laptop. The answer appears in its own Chrome window. The text does not go to a cloud service. There is no extension to install.

1Show the bookmarks bar

Press Ctrl+Shift+B in Chrome. Do this step only if you do not see the bar.

2Drag each button to the bookmarks bar

Hold the mouse button down on a button below, move it to the bookmarks bar, then release it. Do this for all four buttons.

Each bookmark contains a small script, not a web address. If Chrome asks for a name, keep the name that it shows.

3Test the chat window

Caution: Llama must run (its icon is in the system tray), because the Llama server shows the chat page. Close your old Llama chat windows before the test.

Expected: a separate Chrome window opens at the right side of the screen with the Llama chat page. It sends "Reply with the word OK only." by itself, and Gemma answers. You can move, resize and minimize the window.

4Use the buttons

  1. Select text on any web page. To send the whole page, select nothing.
  2. Click a button on the bookmarks bar.
  3. A Llama chat window opens and sends the instruction and the text by itself. You do not press Enter. If no model is loaded, the window loads Gemma first (about 10 seconds).
  4. Read the answer. You can type a follow-up question in the window. Close the window when you are done.

5How much text a button sends

  • Text longer than 7,000 characters is cut to 7,000. The prompt then ends with "[The text was cut. Only the start is included.]".
  • Why 7,000: the model reads at most 4096 tokens, the question and the answer together. In a test, 12,000 characters of a Wikipedia page became 4,421 tokens, and the server refused the request. 7,000 characters became about 1,600 tokens.
  • The window address can have at most 30,000 characters (the server accepted a 30,000-character address in a test). English text always fits. Text in Chinese, Japanese, Russian or Greek uses up to 9 address characters for each letter, so the button cuts it to about 3,300 letters.

6Limits

  • The buttons do not work on chrome:// pages, in the Chrome PDF viewer, or on a few sites that block scripts from bookmarks.
  • Text inside a frame from a different website cannot be read. The button then uses the whole page.
  • With no selection, a button sends the main part of the page (the <main> element, or the only <article>), without the side menus and the footer. If the page has no main part of at least 500 characters, it sends all the visible text.
  • The Reply button writes a draft only. You copy it, paste it, check it and send it yourself.
  • The chats are kept in the chat page's list of recent conversations, in this Chrome profile only.

7Known problems

  • Close the chat windows after you read the answer. Each open chat window keeps one connection to the Llama server, and Chrome allows 6 connections to one server. In a test with 5 chat windows open, the next window sent nothing and showed no answer.
  • Summarize page can show a turning circle and no answer. In tests, the first long prompt in a browser session was answered on the page. Later long prompts were answered by the server, but the chat page did not show the answer. The same occurred with a 3,000-character limit. The cause is in the llama.cpp chat page, and I did not find a workaround. Short selections (Explain, Translate, Reply) were not affected in the same tests.
  • The buttons no longer use the Llama overlay or llama:// links, so the Llama crash that closed the overlay (12 of 23 handoffs in a test) does not affect them.
